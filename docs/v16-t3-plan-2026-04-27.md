| 자료 | 결과 |

| Android **Foreground Service** docs | startForegroundService + ServiceCompat.startForeground + FOREGROUND_SERVICE_TYPE_SPECIAL_USE |

### 1.2 핵심 발견

#### iOS

- **AlarmKit ↔ ActivityKit 자동 통합:** `AlarmAttributes : ActivityAttributes` (swiftinterface L16) → AlarmKit 알람이 자동으로 Live Activity 표시
- **AlarmKit Opt-B 정공:** `AlarmConfiguration.alarm(... stopIntent: AppIntents.LiveActivityIntent? ... )` (swiftinterface L257-259)
- **ActivityKit iOS 16.1+** / **iOS 26.0+** 에서 `Activity.request(... alertConfiguration: start:)` 추가
- **DynamicIsland 4 region:** expanded / compactLeading / compactTrailing / minimal
- **App Group entitlement** 필수 (Widget ↔ App 데이터 공유)

#### Android

- **FOREGROUND_SERVICE_TYPE_SPECIAL_USE** (API 34+) — routine timer 같은 일반 시나리오용
- **PRIORITY_LOW 이상 알림 + ID ≠ 0** 필수
- **PendingIntent + FLAG_IMMUTABLE** 으로 action 버튼

### 1.3 LiveActivityIntent 패턴 (확정)

```swift
struct StopRoutineIntent: LiveActivityIntent {
    static var title: LocalizedStringResource = "Stop Routine"
    @Parameter(title: "Routine ID") var routineId: String

    func perform() async throws -> some IntentResult {
        // routine stop logic
        return .result()
    }
}
```

### 15.3 §8-2 부분 단순화 — `live-activity-bridge` 유지 필수

플랜 창 발견: `AlarmAttributes : ActivityAttributes` (AlarmKit swiftinterface L16) → AlarmKit 알람 등록 시 시스템 자동 LiveActivity 생성.

**그러나 — routine 진행 시점 분리:**

| 시점 | LiveActivity 표시 | Bridge 필요 |
|------|----------------|----------|
| **routine 시작 (첫 step)** | `Activity.request()` 직접 호출 | ✅ |
| **step 진행 중 (카운트다운 갱신)** | `Activity.update()` 직접 호출 | ✅ |
| **chain 알람 발화** (다음 step 시작) | AlarmKit AlarmAttributes 자동 (Opt-B) | ❌ 자동 |
| **confirm_prompt 알람 발화** | AlarmKit AlarmAttributes 자동 | ❌ 자동 |
| **routine 종료** | `Activity.end()` 직접 호출 | ✅ |

→ **§2 #8 `modules/live-activity-bridge/` 유지 필수.** AlarmKit 만으로는 알람 시점만 표시 → step 진행 중 비표시 = UX 불완전. 단 AlarmKit 알람 시점 처리 코드는 단순화 (자동).

### 15.4 §8-5 Opt-B 라인 명세 (Phase 5)

**확정 패턴:**

```swift
// targets/widget/NextStepIntent.swift (Phase 5 신규)
@available(iOS 26.0, *)
struct NextStepIntent: LiveActivityIntent {
  static var title: LocalizedStringResource = "다음 step 진행"

  @Parameter(title: "Routine ID") var routineId: String
  @Parameter(title: "Next Step Index") var nextStepIndex: Int

  func perform() async throws -> some IntentResult {
    // 다음 step 진행 + 다음 알람 등록
    return .result()
  }
}
```

```swift
// AlarmkitBridgeModule.swift Phase 5 — scheduleAlarm 본문 갱신
let intent = NextStepIntent(routineId: params.routineId, nextStepIndex: params.nextStepIndex ?? 0)
_ = try await AlarmManager.shared.schedule(
  id: id,
  configuration: .alarm(
    schedule: schedule,
    attributes: attributes,
    stopIntent: intent  // v1.6 T1 Opt-B (메모리 project_alarmkit_t1.md 결정 4)
  )
)
```

**Opt-A → Opt-B 마이그 흐름:**
1. T1 의 `OnStartObserving` Task 보존 (iOS 25 이하 fallback + Opt-B 미지원 시)
2. iOS 26+ 에서 stopIntent 추가 → 사용자 stop 누름 → 시스템이 perform() 자동 호출
3. perform() 본문 = 다음 step 진행 + 다음 알람 등록 (앱 진입 불필요)
4. 앱 kill 상태에서도 시스템 보장 실행 — Opt-A 한계 (Task 백그라운드 보장 불확실) 완전 해소
