# ShutTimer Repeat-Mistake List

**Initial draft:** 2026-04-07 (extracted from accumulated mistake patterns in the moda project)
**Purpose:** All windows (Plan / Build / QA / Deploy) MUST read this before any task. Repeat the same mistake → stop immediately.

---

## 1. False / Inaccurate Reporting [Critical]

| Pattern | Source | Prevention |
|---------|--------|-----------|
| Reporting partial completion as full PASS | moda N-4, C-9 | Completion reports require a 1:1 reconciliation table of handoff items vs actual modifications |
| Recording unverified items as PASS | moda many | If unverified, mark as "unverified". Never PASS by guess |
| Treating "code exists" as "feature works" | moda C-9 | grep does not equal verification. PASS only after execution check |
| Hiding incompletes so they look complete | moda D-6 | Always state incompletes explicitly. Intentional omission = false reporting |
| Reporting error causes by guess | moda 6-3 | Read the code and confirm the flow before reporting. If unknown: "investigating" |

## 2. Window Role Violations [Critical]

| Pattern | Source | Prevention |
|---------|--------|-----------|
| Plan window modifying code / running builds | moda 8-2 | Plan window stops at analysis + plan. Execution belongs to the appropriate window |
| Deploy window modifying code | moda 8-1 | Deploy window only deploys. On finding issues: report cause, wait for Build window |
| Acting without instructions | moda 8-2 | Do nothing until a task is explicitly instructed |
| Writing code into the handoff doc | moda many | Handoffs contain spec/behavior only. Code is written by the Build window |

## 3. Missing Related Files / Components [High]

## 7. No-Test-Environment Implementation Forbidden [Critical]

| Pattern | Source | Prevention |
|---------|--------|-----------|
| Stacking native-module code in an untestable state | ShutTimer 2026-04-11 | Follow the mandatory workflow below |
| Reporting "buildable" for features Expo Go cannot test | ShutTimer 2026-04-11 | Without a test environment: report "cannot verify" |
| Repeated coding without a dev build | ShutTimer 2026-04-11 | Native changes require a dev build first |

### Mandatory Workflow (Stop on Violation)

```
1. Plan → write the plan
2. Secure dev build (eas build --local --profile development)
   → install on device → secure test environment
3. Implement → live device test → fix bugs → verify
   (JS change: hot reload)
   (Native change: rebuild dev build)
4. Full verification
5. Production build (release, once)
```

**No implementation start without a dev build. No "buildable" reports without a test environment.**

## 8. Common Rules (All Windows)

1. **Before "complete", reconcile every handoff item 1:1.** Anything missed = not complete.
2. **No false reporting.** If you didn't do it, say so. Never report partial as full PASS.
3. **"Check / review" = check and report only.** Execution requires separate approval.
4. **No guess reporting.** If you don't know: "investigating". Read the code first.
5. **No acting without instructions.** Even after session restore, wait for user instruction.
6. **Each window stays in its role.** Cross the line → stop immediately.
